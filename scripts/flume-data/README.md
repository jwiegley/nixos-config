# flume-data

Python codebase for Phase 2 (weekly cross-check) and Phase 3 (historical
backfill) of the water attribution feature.

## Layout

- `flume_data/detection.py` — pure pattern-detection algorithm
- `flume_data/config.py` — loads `zones.json` (generated by Nix module)
- `flume_data/day_cache.py` — per-local-day sample cache; owns the rule that
  a cached day counts only once it records a fully-elapsed window
- `flume_data/sources/` — Flume API, VictoriaMetrics, HA Postgres
- `flume_data/destinations/` — CSV, VM line protocol, HA LTS
- `flume_data/cross_check.py` — Phase 2 orchestrator
- `flume_data/backfill.py` — Phase 3 orchestrator
- `flume_data/report.py` — Weekly water report rendering
- `flume_data/classify_v2.py` — v2 segment classifier (B-Hyve irrigation suppression)
- `flume_data/classify_v3.py` — v3 probabilistic per-fixture classifier
- `flume_data/fixtures.py` — calibrated fixture signature library
- `flume_data/irrigation_sessions.py` — B-Hyve valve session extraction
- `flume_data/dishwasher.py` — Miele dishwasher cycle extraction
- `flume_data/tankless.py` — Navien hot-water-flow reader
- `tests/` — pytest suite

One-shot operator scripts live at the top level, outside the package:
`flume_db_sync.py`, `backfill_v2.py`, `backfill_v3.py`,
`refresh_minute_attributions.py`, `emit_segments_csv.py`.

## Running the tests

    cd /etc/nixos/scripts/flume-data
    nix-shell -p 'python3.withPackages (ps: with ps; [ pytest pytest-mock responses freezegun requests psycopg2 websocket-client python-dateutil ])' \
      --run 'python -m pytest -v'

## Configuration

`zones.json` is generated by the Nix module
`services.home-assistant-water-attribution` and materialized at
`/var/lib/flume-data/zones.json` (the
`services.home-assistant-water-attribution.zonesJsonOutputPath` default). Do not edit
it by hand — changes will be overwritten on next `nixos-rebuild switch`.

## CLI

`flume-data` is the argparse `prog` name only — **no executable by that name is
installed anywhere** (verified 2026-07-27). Every real invocation is
`python -m flume_data …` from the units in `modules/services/flume-data.nix`,
which set `PYTHONPATH=/etc/nixos/scripts/flume-data`,
`FLUME_AUTOFILL_CONFIG=/var/lib/flume-data/zones.json` and a Python env carrying
`requests` / `psycopg2` / `websocket-client`. See
`docs/WATER_ATTRIBUTION.md` for a working ad-hoc recipe.

    python -m flume_data cross-check --days 7
    python -m flume_data backfill --discover
    python -m flume_data backfill --from 2024-01-01 --to 2024-12-31 [--dry-run]
    python -m flume_data backfill --promote --through 2026-05-21
    python -m flume_data backfill --unpromote --through 2026-05-21
    python -m flume_data detect --input <csv>      # stub: raises NotImplementedError
