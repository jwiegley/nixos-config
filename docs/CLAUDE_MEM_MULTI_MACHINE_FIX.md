# claude-mem — Multi-Machine Fix Guide (hera + other Ubuntu/NixOS hosts)

Companion to `docs/CLAUDE_MEM_NIXOS_REPAIR.md` (the vulcan deep-dive). This one is
**portable and diagnostic-driven**: it tells you which of the issues apply on a
given machine and exactly how to fix each, per platform.

> **Why this isn't one-size-fits-all:** the problems split into (1) NixOS-only
> native-library issues, (2) systemd-user-service environment issues (Linux), and
> (3) a cross-platform "generator routing" issue that comes from *your shared
> dotfiles*. A Mac needs only #3; an Ubuntu box usually needs #3 (+ maybe a PATH
> tweak); a NixOS box needs all three.

Established facts about the setup (from vulcan, 2026-05-27):
- `claude-mem` runs as a Claude Code **plugin** (via npx / plugin cache), and it
  **installs its own** persistent worker: `~/.local/bin/claude-mem-worker` +
  `~/.config/systemd/user/claude-mem-worker.service` (both plain files, **not**
  managed by your nix-config). So systemd-level fixes are **per-machine
  drop-ins/overrides** you layer on top (optionally generated by nix-config).
- Your `claude` on `$PATH` is a 56-byte wrapper → `exec ai` (the hera gateway),
  defined in the shared `johnw/nix-config` (`git+ssh://gitea/johnw/nix-config`).
  The **real** Claude Code is the home-manager/npm `claude-code` binary.
- claude-mem 13.x still uses ChromaDB via `uvx chroma-mcp`; v13 also has an opt-in
  `CLAUDE_MEM_RUNTIME=server-beta` (Postgres FTS) — default is `worker` (Chroma).

---

## The five issues at a glance

| # | Issue | Symptom | NixOS | Ubuntu/FHS | macOS |
|---|-------|---------|:-----:|:----------:|:-----:|
| A | Worker can't find `uvx`/`claude` (stripped systemd-user PATH) | `Executable not found in $PATH: "uvx"` | **Yes** | Maybe* | n/a† |
| B | chroma wheels can't load `libstdc++.so.6`/`libz.so.1` | `ImportError: libstdc++.so.6` → MCP `Connection closed` | **Yes** | No | No |
| C | Generator routed through `ai` wrapper | `JSON Parse error: Unexpected identifier "Preflight"`, `SDK agent start failed: 404` | **Yes** | **Yes** | **Yes** |
| D | Worker doesn't auto-restart on upgrade | stale behavior, old version keeps running | Yes | Yes | Yes |
| E | New `memory_*`/`observation_*` tools error in default runtime | `requires CLAUDE_MEM_RUNTIME=server-beta` | info | info | info |

\* Ubuntu systemd **user** services also get a reduced PATH; you hit A only if
`uvx`/`claude` live somewhere not on it (e.g. `~/.local/bin`, pipx, cargo).
† macOS has no systemd; the worker is a launchd agent or spawned by Claude Code, so
the systemd-PATH form of A doesn't apply (but make sure `uvx` is findable).

**Issue C is the one that will bite every machine using your shared dotfiles**, so
treat it as the universal must-fix.

## Step 0 — Diagnose any machine (copy-paste)

```bash
# ---- claude-mem machine diagnostic (safe: prints only paths/counts) ----
echo "OS=$(uname -s)  NixOS=$([ -e /etc/NIXOS ] && echo yes || echo no)"

# Worker: systemd user service or not?
if systemctl --user status claude-mem-worker.service >/dev/null 2>&1; then
  echo "worker: systemd user service"
else
  echo "worker: NOT systemd (macOS launchd / Claude-Code-spawned)"
fi

# Worker env (Linux only)
WPID=$(pgrep -f 'worker-service\.cjs --daemon' | head -1)
if [ -n "$WPID" ] && [ -r "/proc/$WPID/environ" ]; then
  echo "worker PID=$WPID version=$(tr '\0' '\n' </proc/$WPID/cmdline | grep -o 'claude-mem/[0-9.]*' | head -1)"
  tr '\0' '\n' < "/proc/$WPID/environ" | grep -E '^(PATH|LD_LIBRARY_PATH)=' || echo "  (PATH/LD_LIBRARY_PATH unset)"
fi

# Issue C: does 'claude' resolve to the real binary or the ai wrapper?
CLI=$(command -v claude 2>/dev/null); REAL=$(readlink -f "$CLI" 2>/dev/null)
echo "claude: $CLI -> ${REAL:-not found}"
case "$REAL" in
  *claude-code*) echo "  OK: real claude-code" ;;
  "")            echo "  claude not found" ;;
  *)             echo "  !! NOT claude-code (likely the 'ai' wrapper) -> Issue C applies" ;;
esac

# What does claude-mem think CLAUDE_CODE_PATH is?
echo "claude-mem CLAUDE_CODE_PATH=$(jq -r '.CLAUDE_CODE_PATH // "(unset)"' ~/.claude-mem/settings.json 2>/dev/null)"

# Recent failure fingerprints in the worker log
LOG=$(ls -t ~/.claude-mem/logs/*.log 2>/dev/null | head -1)
[ -n "$LOG" ] && for p in 'uvx.*not found\|Executable not found' 'libstdc++\|ImportError\|Connection closed' 'Preflight\|JSON Parse error'; do
  printf "  log hits [%s]: %s\n" "$p" "$(grep -ciE "$p" "$LOG")"
done
```

Read the output:
- `NixOS=yes` → issues **A + B** likely apply.
- `claude -> … NOT claude-code` → issue **C** applies (almost certainly true everywhere you use the shared dotfiles).
- log hits > 0 for a pattern → that issue is actively firing.

## Fix C (do this everywhere) — point claude-mem at the real Claude Code

claude-mem's generator drives the headless `claude` **stream-json SDK**; the `ai`
gateway can't speak that protocol and prepends a `Preflight` banner → JSON parse
fails. Fix = make claude-mem use the real `claude-code` binary, not the wrapper.

**Find the real binary on the machine** (must resolve to `…claude-code…`, not `ai`):
```bash
for c in "$HOME/.local/bin/claude" "$(npm prefix -g 2>/dev/null)/bin/claude" \
         /etc/profiles/per-user/"$USER"/bin/claude "$HOME/.claude/local/claude"; do
  r=$(readlink -f "$c" 2>/dev/null); case "$r" in *claude-code*) echo "REAL: $c -> $r"; break;; esac
done
```

**Apply (any OS):** write it into claude-mem's settings (it's a mutable file; edit
in place, don't symlink):
```bash
f=~/.claude-mem/settings.json
cp -p "$f" "$f.bak.$(date +%s)"
tmp=$(mktemp "$(dirname "$f")/settings.json.XXXXXX")
jq --arg p "$HOME/.local/bin/claude" '.CLAUDE_CODE_PATH=$p' "$f" >"$tmp" \
  && chmod --reference="$f" "$tmp" && mv "$tmp" "$f"     # <-- use the REAL path you found
```
Then restart the worker (see Fix D) and confirm `0` Preflight hits in the log.

> **Trade-off (applies on every machine):** this routes claude-mem's observation
> generation through your **direct Claude Code auth, not hera**. That's deliberate
> for a low-stakes background task. If you want to keep it on hera, instead set
> claude-mem's OpenRouter/OpenAI provider (`CLAUDE_MEM_PROVIDER` + the
> `CLAUDE_MEM_OPENROUTER_*` keys) to a hera OpenAI-compatible endpoint, and leave
> `CLAUDE_CODE_PATH` unset.

## Fix A (Linux, mainly NixOS) — give the worker a usable PATH

systemd **user** services don't inherit your login shell. The worker needs `uvx`
(for chroma) and, unless C set an absolute `CLAUDE_CODE_PATH`, `claude`.

**NixOS** — `uvx` lives in your per-user nix profile, absent from the service PATH.
**Ubuntu** — only needed if `uvx`/`claude` are in `~/.local/bin`/pipx/cargo.

Drop-in (works on both; adjust dirs):
```ini
# ~/.config/systemd/user/claude-mem-worker.service.d/override.conf
[Service]
# NixOS:
Environment=PATH=/etc/profiles/per-user/USER/bin:/run/current-system/sw/bin:/run/wrappers/bin
# Ubuntu (example):
# Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin
```
```bash
systemctl --user daemon-reload && systemctl --user restart claude-mem-worker.service
```

## Fix B (NixOS only) — let chroma's manylinux wheels load

`uvx chroma-mcp` installs prebuilt wheels (numpy/chromadb) that `dlopen`
`libstdc++.so.6`/`libz.so.1` from FHS paths NixOS lacks. Point them at **nix-ld**'s
curated library set (same drop-in as Fix A):
```ini
[Service]
Environment=LD_LIBRARY_PATH=/run/current-system/sw/share/nix-ld/lib
```
Prerequisites on that host:
```nix
programs.nix-ld.enable = true;
# default library set usually includes libstdc++ + zlib; if a host's set is thin:
# programs.nix-ld.libraries = with pkgs; [ stdenv.cc.cc.lib zlib ];
```
Verify: `LD_LIBRARY_PATH=/run/current-system/sw/share/nix-ld/lib uv run --python 3.13 --with chromadb python -c 'import chromadb;print("ok")'`
should print `ok`. (On a host without nix-ld, use
`LD_LIBRARY_PATH=${pkgs.stdenv.cc.cc.lib}/lib:${pkgs.zlib}/lib` instead.)

## Fix D (all) — restart the worker after every claude-mem upgrade

claude-mem updates do **not** restart the persistent worker; it keeps running the
old version until you bounce it.
```bash
# Linux/systemd:
systemctl --user daemon-reload && systemctl --user restart claude-mem-worker.service
# verify it's the new version:
tr '\0' '\n' < /proc/$(pgrep -f 'bun.*worker-service.cjs --daemon'|head -1)/cmdline | grep -o 'claude-mem/[0-9.]*'
# macOS: kill it and let the SessionStart hook respawn, or restart its launchd agent:
pkill -f 'worker-service.cjs --daemon'
```

## Note E (all, v13+) — runtime vs tools

Default runtime is `worker` (ChromaDB) → use `search`/`timeline`/`get_observations`.
The `memory_*`/`observation_*` MCP tools require `CLAUDE_MEM_RUNTIME=server-beta`
(Postgres FTS) and will otherwise error with a pointer back to the worker tools.
Don't enable server-beta unless you intend to migrate; it's a separate backend.

## Per-platform recipe (TL;DR)

**hera / any machine — first run Step 0, then:**

- **macOS (Darwin):** only **Fix C** (+ Fix D after upgrades). No PATH/lib fixes.
  Confirm `uvx` is installed and on the launchd/Claude-Code-inherited PATH.
- **Ubuntu / other FHS Linux:** **Fix C**; add **Fix A** only if Step 0 shows the
  worker's PATH lacks `uvx`/`claude`. **Skip Fix B.**
- **NixOS:** **Fix C + Fix A + Fix B** (the A/B drop-in is one file). Ensure
  `programs.nix-ld.enable = true`.

## Where to encode it declaratively (your nix-config layout)

You keep cross-platform home config in the shared `johnw/nix-config` (the
"hera"/Darwin repo), and vulcan consumes it as a non-flake input + stubs
`programs.git-ai`. So:

| Piece | Home | Why |
|-------|------|-----|
| **Fix C** (`CLAUDE_CODE_PATH` → real claude) | **shared `johnw/nix-config`** | cross-machine; beside where `claude-code`/`ai` are defined |
| **Fix A+B** drop-in (PATH + `nix-ld` libs) | **per-host NixOS config** (e.g. vulcan `/etc/nixos`), or shared repo `lib.mkIf (NixOS)` | references `/run/current-system` + nix-ld → NixOS-only |
| Ubuntu hosts | a setup script in your dotfiles repo | no nix; apply Fix C (+A) by hand/script |

**Shared repo — Fix C via home-manager activation** (settings.json is mutable, so
merge rather than symlink; gate to hosts where claude-mem runs):
```nix
home.activation.claudeMemRealClaude = lib.hm.dag.entryAfter [ "writeBoundary" ] ''
  f="$HOME/.claude-mem/settings.json"
  [ -f "$f" ] && ${pkgs.jq}/bin/jq \
    '.CLAUDE_CODE_PATH = "'"$HOME"'/.local/bin/claude"' "$f" > "$f.tmp" && mv "$f.tmp" "$f"
'';
```

**Per-host NixOS — Fix A+B drop-in via home-manager:**
```nix
xdg.configFile."systemd/user/claude-mem-worker.service.d/override.conf".text = ''
  [Service]
  Environment=PATH=${config.home.profileDirectory}/bin:/run/current-system/sw/bin:/run/wrappers/bin
  Environment=LD_LIBRARY_PATH=/run/current-system/sw/share/nix-ld/lib
'';
# (then `home-manager switch` / `nixos-rebuild switch`; remove any hand-written
#  override.conf first so HM can own the file)
```

> Note: `claude-mem` owns the worker `.service` unit itself, so manage only the
> `.service.d/override.conf` **drop-in** (above), never the main unit.

## Verification checklist (per machine)

1. `claude-mem` search returns results (worker-mode `search` tool).
2. Worker log shows `0` hits for `uvx not found`, `libstdc++`, `Preflight`.
3. New observations appear (`CHROMA_SYNC Syncing observation [obs N]` climbing).
4. After any upgrade: `/proc/<pid>/cmdline` shows the new `claude-mem/<ver>`.
```bash
LOG=$(ls -t ~/.claude-mem/logs/*.log|head -1)
grep -ciE 'uvx.*not found|libstdc\+\+|Preflight|JSON Parse error' "$LOG"   # want: 0
```
